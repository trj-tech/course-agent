# course-agent 需求文档

> 产品名：校园课程智能助手（仓库名：course-agent）

## 1. 项目定位

做一个"能查真实数据、能按文档作答、能帮你存计划"的 AI 课程助手，完整落地 **MCP + Agent + RAG** 三种能力的分工与串联。

## 2. 目标用户

- 在校学生（核心用户）
- 课程管理员（可选，维护课程与课表数据）

## 3. 角色与权限

| 角色 | 能力 | 数据范围 |
| --- | --- | --- |
| student 学生 | 登录、查询自己的课表、上传课程资料、基于资料问答、生成并保存学习计划 | 仅本人数据 |
| admin 管理员 | 维护课程、课表数据（第二阶段，可选） | 全部课程数据 |

## 4. 功能需求

### 4.1 学生侧

**F1 登录认证**
- 学生账号密码登录，后端签发 token（JWT）
- 所有 Agent 请求携带用户身份，作为权限隔离的依据

**F2 课表查询（真实数据）**
- 对话式查询："我今天有什么课？"、"周三下午有课吗？"
- 数据来源：schedules 表，查询强制限定当前用户（`WHERE user_id = ?`）

**F3 课程资料上传与管理**
- 上传课程资料（PDF / DOCX / TXT / MD）
- 上传后自动切片、向量化，供 RAG 检索

**F4 基于资料的问答（RAG）**
- 只依据已上传资料作答；资料中没有的内容，明确说明"资料中未找到"，不编造
- 回答中标注引用来源（哪个文档、哪一段）

**F5 学习计划生成与保存**
- 根据课表 + 资料，让 Agent 生成学习计划
- 计划保存到数据库，可查看历史计划

### 4.2 管理员侧（第二阶段，可选）

**F6 课程管理**
- 维护课程信息与课表安排

## 5. 非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| N1 | 权限隔离 | 多用户下 Agent 不得越权查询/修改他人数据，所有业务工具强制携带当前用户 id |
| N2 | 幻觉控制 | 约束模型仅基于检索到的资料作答，检索为空时明确拒绝 |
| N3 | 实时推送 | 工具调用过程（查库 / 检索 / 保存）通过 SSE 实时推送到前端展示 |
| N4 | 可演示性 | 本地一键启动，预置演示账号与模拟数据 |

## 6. 技术架构

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite | 聊天界面、SSE 工具调用过程展示、计划列表、资料上传 |
| 后端 | FastAPI | REST API、登录认证、SSE、文件上传 |
| 工具层 | MCP | 把课表查询、计划保存等业务能力封装成标准工具 |
| 智能体 | LangChain ReAct Agent | 解析用户意图，决定调用哪些工具、组织回答 |
| 知识库 | RAG（向量化 + 检索） | 文档切片、向量化、相似度检索 |
| 数据库 | SQLite（开发）/ MySQL（可选）+ SQLAlchemy | 业务数据落库 |

## 7. 核心流程（示例对话）

```
用户：帮我查一下我明天的课表
  → Agent 调用 MCP 工具 get_my_schedule(tomorrow)
  → 后端按当前用户 id 查库并返回
  → Agent 组织回答 → 工具调用过程经 SSE 推送 → 前端实时展示

用户：上传《Python 程序设计》讲义
  → 文档切片 → 向量化 → 存入知识库

用户：根据讲义讲讲什么是装饰器
  → RAG 检索相关片段 → Agent 依据片段作答（带引用）

用户：帮我制定下周的学习计划
  → Agent 获取课表 + 检索资料 → 生成计划 → 调用工具保存到 study_plans
```
